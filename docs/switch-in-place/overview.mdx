## What every page changes

| Their field | Deepdub field |
|-------------|---------------|
| The spoken text (`text` or `transcript`) | `targetText` |
| Their voice id | `voicePromptId` — pick a preset from [Voice Presets](/voice-presets) |
| Their model id | `model` set to `dd-etts-4.0` |
| Their API key header | `x-api-key` |
| MP3, Opus, or μ-law output | `format` of `mp3`, `opus`, or `mulaw` on `POST /api/v1/tts` |
| WAV or raw PCM | [Streaming Out](/api-reference/websocket/overview) with `format` `wav` or `s16le` |

The REST response body is the audio. Keep the `x-generation-id` response header — it is what you quote when [reporting a problem](/api-reference/issues/create-issue) with that generation.

Snippets use the US host, `https://restapi.deepdub.ai/api/v1`. A key provisioned in the EU uses `https://restapi.eu.deepdub.ai/api/v1`. Streaming Out is `wss://wsapi.deepdub.ai/open` in the US and `wss://wsapi.eu.deepdub.ai/open` in the EU.

## What stays on the vendor

- Voice ids. A Deepdub `voicePromptId` is a different id. The samples use the Storyteller preset (`bd1b00bb-be1c-4679-8eaa-0fcbfd4ff773`) as a stand-in.
- Model ids. Send `dd-etts-4.0`.
- Pronunciation-dictionary ids and word timestamps. `POST /tts` returns audio bytes.

When the text arrives in pieces from an LLM, use [Streaming In and Streaming Out](/api-reference/websocket/streaming) instead of one `POST`.
